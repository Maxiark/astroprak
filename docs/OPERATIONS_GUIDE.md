# Руководство администратора и преподавателя Astrosite (v2.1)

## 1. Управление конфигурацией и токенами

Токен администратора, настройки БД и интервал регулярного резервного копирования задаются в файле `infra/.env` хост-машины:
```bash
ADMIN_TOKEN=сложный_секретный_токен_администратора
POSTGRES_PASSWORD=надежный_пароль_базы_данных
COOKIE_SECURE=0 # Установить 1 при работе через чистый HTTPS
BACKUP_INTERVAL_MINUTES=30 # Интервал автобэкапа таблицы попыток (в минутах)
```

Если переменная `ADMIN_TOKEN` не задана в `.env`, по умолчанию используется `dev-admin`.

## 2. Сценарий проверки домашних заданий и аналитики сессий

1. **Действия ученика:**
   * Открывает задачу и выполняет измерения.
   * При закрытии вкладки или смене устройства восстанавливает работу по 32-значному коду через пункт **«Ключ»** $\rightarrow$ **«Восстановить сессию»**.
   * Нажимает кнопку сдачи: система мгновенно проверяет ответ, выводит балл и протокол проверки, а также сохраняет запись в БД и в непрерывный резервный лог на диске.
   * Копирует 32-значный код сессии и отправляет учителю.

2. **Действия учителя в разделе «Аналитика сессий» (`/admin`):**
   * **Сквозной поиск по всей базе:** Строка поиска ищет по коду участника, `#ID` попытки или названию задачи сразу по **всем** записям в БД, независимо от текущей страницы.
   * **Пагинация и догрузка:** По умолчанию загружаются последние 100 записей; кнопки **«← Пред. 100» / «След. 100 →»** позволяют листать страницы, а кнопка **«+ Догрузить ещё 100 в этот список»** добавляет следующую сотню строк в текущую таблицу.
   * **Сворачивание коротких сессий (`< 5 с`):** Короткие незавершённые сессии (менее 5 секунд) по умолчанию автоматически группируются в компактные сворачиваемые строки `▶ Свёрнуто коротких сессий (< 5 с): N шт.`, чтобы не отвлекать при проверке. Также можно включить галочку **«Скрыть < 5 с при загрузке с сервера»**.
   * **Выгрузка результатов и логов действий по всем работам:**
     * **«📥 Ведомость попыток (CSV)»** — сводная таблица всех попыток с оценками, ответами и JSON-логом действий.
     * **«📋 Лог действий по всем работам (CSV)»** — сквозной хронологический журнал всех действий всех учеников для анализа в Excel/Python.
     * **«🗂 Все работы + логи (JSON)»** — полный структурированный JSON-архив всех попыток вместе с их событиями.

## 3. Регулярное резервное копирование и восстановление

1. **Автоматический бэкап:**
   * Каждые 30 минут (и при старте ядра) сервис `core` автоматически сохраняет полный снимок таблиц `users`, `attempts` и `events` в директорию `data/backups/` (и зеркалирует `latest_backup.zip` и `attempts_latest.csv` в `data/tasks/_backups/`).
   * Внутри каждого архива `backup_YYYY-MM-DD_HH-MM-SS.zip` находятся:
     * `attempts_with_codes.csv` — готовая таблица попыток с кодами участников, баллами и ответами;
     * `events_log.csv` — полный журнал действий;
     * `full_restore_dump.json` — полный дамп для автоматического восстановления БД.
   * Кроме того, в момент каждой сдачи работы (`POST /api/attempts/{id}/submit`) результат мгновенно дописывается в файлы `submitted_live_log.csv` и `submitted_live_log.jsonl`.

2. **Управление через веб-интерфейс (вкладка «Резервные копии» в `/admin`):**
   * Кнопка **«⚡ Создать полный бэкап сейчас»** создаёт внеочередной снимок.
   * Любой архив можно скачать прямо из таблицы.
   * В блоке **«Восстановление базы попыток»** можно загрузить `latest_backup.zip` или `full_restore_dump.json` для полного восстановления всех попыток и кодов участников после сбоя или при переезде на новый сервер.
