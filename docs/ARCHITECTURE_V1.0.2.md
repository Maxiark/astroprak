# Архитектурный манифест и устройство ядра Astrosite v1.0.2

## 1. Концепция и фундаментальные догмы

1. **Неприкосновенность ядра:** Никакие изменения файлов задач (манифесты, генераторы, виджеты, разметка) не требуют пересборки контейнеров (`pnpm build`, `docker compose build`) или перезапуска демона ядра[cite: 28]. Директория задач вынесена на внешний Docker Volume (`./data/tasks:/app/data/tasks`)[cite: 28].
2. **Принцип «песчаного замка» (Graceful Degradation):** Поломка отдельной задачи полностью изолируется на уровне сканера `task_loader.py`[cite: 20, 28]. Сервер логирует инцидент, исключает сломанную задачу из публичного каталога и возвращает `422 Unprocessable Entity` только для текущего проблемного запроса[cite: 20, 28].
3. **Изоляция исполнения интерфейса (Iframe Sandbox):** Каждый интерактивный тренажёр отображается в песочнице `<iframe>`[cite: 28]. Любые ошибки в JavaScript-коде задачи не затрагивают основное React-приложение и не вызывают «белый экран»[cite: 28].
4. **Анонимность и отсутствие ПДн:** Идентификация построена вокруг 128-битных токенов в `HttpOnly`-cookie[cite: 28]. Ключ служит открытым кодом сессии, который ученик прикрепляет в электронный журнал для отчётности[cite: 28].
5. **Встроенная автопроверка (Decoupled Grading):** Ядро не содержит жестко закодированных правил проверки физических величин. Каждая задача в `generator.py` объявляет собственную функцию `grade(seed, answers)`[cite: 26]. Ядро лишь вызывает её и сохраняет результаты[cite: 23].
6. **Единая библиотека визуализации (`_shared`):** Общий математический аппарат графиков, луп, прилипания к точкам (SNAP) и измерительных линеек вынесен в `/data/tasks/_shared/` и раздаётся ядром по HTTP, не дублируясь в тысячах строк кода виджетов[cite: 23].

## 3. Модель данных (PostgreSQL)

База данных работает в схеме `astrosite_v2` и автоматически накатывает изменения колонок при старте (`init_db`):

* `users`: хранит хеш ключа (`key_hash`) и открытый токен (`raw_key`).


* `attempts`: сохраняет привязку к пользователю (`user_id`), `task_id`, `seed`, вариант (`task_data`), ответы (`answers`), отметку сдачи (`submitted_at`), итоговый балл (`score`) и подробный JSON вердикта автопроверки (`grading`).


* `events`: хронологический журнал действий пользователя.



### Жизненный цикл попытки (Attempt Lifecycle)

1. **Создание / Восстановление:** `POST /api/attempts` возвращает существующую незавершённую попытку (или создаёт новую). Если попытка уже сдана, возвращаются сохранённые `answers`, `score` и `grading`.
2. **Промежуточное сохранение:** Виджет шлёт `ASTROSITE_ANSWER_CHANGE`, хост с debounce отправляет `PATCH /api/attempts/{id}/answers`.


3. **Сдача и автопроверка:** Виджет инициирует `ASTROSITE_SUBMIT_ATTEMPT`. Хост отправляет `POST /api/attempts/{id}/submit`. Сервер вызывает `grade(seed, answers)` из генератора задачи, записывает `score` и `grading` в базу и возвращает их клиенту. Виджет подсвечивает поля зелёным/красным и выводит балл.
